Getting started

Download the file for your system from the download section. It is a single program: put it on your own computer and on each host you want to reach, as ~/.local/bin/sshremote on Linux or anywhere on PATH on Windows.

sshremote

With no arguments it opens the open dialog: a new connection, this computer (local shells, its screen and files), your SSH hosts (favorites, recent and ~/.ssh/config), Extensions and the tools. Under this computer is the Remote access by ID card. What you open goes into the workspace as tabs and panes; each pane switches between terminal, screen and files from its mode menu.

KeysDoes
Ctrl+Shift+PCommand palette
Ctrl+Alt+EnterEnter or leave full screen while sharing a screen
Ctrl+]Menu of the terminal viewer: presets, colour, zoom, shell, Ctrl+Alt+Del

Connecting by SSH

The usual way: the viewer runs ssh -T HOST sshremote --agent, so your keys, agent, jump hosts and ~/.ssh/config work unchanged and nothing else needs to be reachable.

sshremote --gui user@host                 # the workspace
sshremote --gui user@host --open files    # straight to the files
sshremote terminal user@host --split db   # terminal panes, split
sshremote user@host                       # the screen in this terminal (sixel)
sshremote user@host --preset 0            # 0 black and white 5 fps .. 4 true colour 60 fps

A lost connection is tried again in the same mode, keeping the shells; after 30 seconds the pane offers Reconnect or Close.

Windows hosts. The agent starts a helper in the logged-on user's session. To see the sign-in screen and send Ctrl+Alt+Del, add the service once (elevated, or with Start with the computer under This computer): sshremote --install-service.

Connecting by ID through the relay

For a PC without SSH or a fixed address, for example a laptop on Wi-Fi, the way RustDesk works. The PC keeps a lasting 9-digit ID, the same across restarts, and a password its owner sets or generates. A viewer connects with both through the relay.

On the PC to reach

Open dialog → This computer → Remote access by ID. The card has an on/off switch, the ID and the password (each with copy, show and new buttons) and a line telling the state. Start with the computer installs the Windows service or a systemd user unit; on Windows the service also covers the sign-in and lock screens. More holds your own password, the relay server and a new ID.

From any browser, without installing anything: open sshremote.dev/web, type the ID and its password, and the screen opens in the page with keyboard and mouse.

On the viewer

Type the ID (digits only) in the open dialog's New connection field, then the password, and choose Screen sharing or Files.

From the command line

sshremote remote-access on           # also: status, off, run
sshremote remote-access password     # a new one; password NEW sets yours
sshremote remote-access id           # a new ID
sshremote remote-access install      # start with the computer; uninstall
sshremote remote-access relay HOST   # use another relay
sshremote sshremote://ID@sshremote.dev --password P

Your own relay

The relay is a small program of its own, sshremote-relay, listening on TCP 7071. To run your own and keep its IDs in a file:

sshremote-relay --listen 0.0.0.0:7071 --store /var/lib/sshremote/ids.json

Using extensions

Browse the extension list, or open Extensions in the app's open dialog (tabs Installed, Browse and Manage). From the command line:

sshremote ext available          # what the signed registry offers
sshremote ext install ID         # install or update
sshremote ext install FILE.sshx  # from a file

The kinds: style packs (pictures and animations behind the terminals), scripts (WebAssembly commands on the selected text, with no file or network access), programs (new sshremote commands such as web and mcp) and resident extensions (status bar items, panels, palette commands, keys and settings). Each request is checked against the permissions in the manifest, shown on the Extensions page.

Building extensions

An extension is a folder with an extension.json manifest. Programs speak JSON-RPC 2.0 over stdin and stdout, one message per line, so any language works. Start from the Rust template, which has a status bar item, a command with a key, a panel, a setting and a form:

sshremote ext new my-extension
sshremote ext dev my-extension

ext dev builds, installs and reloads it in the open app every time a file changes. To share one, pack it with sshremote ext pack DIR OUT.sshx. The manifest, the permissions and the full protocol are in docs/extensions.md.

MCP for AI agents

sshremote mcp HOST (or sshremote mcp --here for this computer) is an MCP server that reads the window in front as text from the accessibility tree and acts on its controls, taking screenshots only when needed. In your agent's MCP configuration:

{"mcpServers": {"remote-pc": {"command": "sshremote", "args": ["mcp", "user@host"]}}}

Security and FAQ

Is anything sent to a server of yours?

Not over SSH: the connection is your own SSH session from end to end. Only the ID and password mode uses the relay.

What can the relay see?

Nothing it could read. The viewer and host agree on a key from the password with SPAKE2, so the password never crosses the network, and seal every message with ChaCha20-Poly1305. The relay only pairs the two and copies sealed bytes.

Can someone take over my ID or guess the password?

An ID is held at the relay by a secret token only your computer has. Each wrong password is answered more slowly than the last, and the relay limits the attempts from each address.

Are passwords stored?

Not unless you choose to. Passwords you choose to save go to the system's password store, and backups of ~/.ssh are encrypted under a passphrase.

How are extensions checked?

The registry's index is signed, each package is checked by its SHA-256, and native extensions are packed per platform. At run time every request is held to the manifest's permissions.

Which systems work?

Hosts: Windows and GNOME on Wayland. Viewers: the native window on Windows and Linux, or a sixel terminal such as Windows Terminal, WezTerm, foot or VTE.
